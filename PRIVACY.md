# Privacy

This document explains, in plain terms, exactly what KeystrokeCounter stores, where it stores it, and what it deliberately does not do. It's more detailed than the [README's privacy section](README.md#privacy) — treat this as the definitive version.

If anything here ever stops matching what the code actually does, that's a bug in this document (or the app) — please [open an issue](https://github.com/adamalnajjar/keystroke_counter/issues).

## What KeystrokeCounter collects

All of the following stays on your Mac and is described in detail in [Where data is stored](#where-data-is-stored):

- **Keystroke counts** — a running total of key presses, overall and per day.
- **Key-frequency information** — how many times each individual key was pressed (e.g. "`a`: 4,213 times"), tallied per day. Auto-repeat from holding a key down is ignored so it doesn't inflate counts.
- **Click counts** — a running total of mouse clicks (left, right, and other buttons), overall and per day.
- **Frontmost application names** — which app was in the foreground when a keystroke or click happened, tallied by app name (or bundle identifier if a name isn't available), so the app can show "top apps by activity."
- **Daily statistics** — the above, bucketed by calendar day, to power the Today/Week/Month views and the history chart.
- **Goals, records, and milestones** — your configured daily goal (if you set one), which lifetime milestones (every 100,000 combined events) have already triggered a notification, and which day the daily-goal notification last fired. This is bookkeeping to avoid repeat notifications, not new categories of activity data.

That's the complete list. There is no category of data collected beyond what's described above.

## What it does NOT collect

KeystrokeCounter does not store, and has no code path capable of producing:

- The sequence or content of what you type — no sentences, words, or messages
- Passwords or any other sensitive text
- Full ordered key sequences of any kind (only per-key frequency counts)
- Screenshots or screen content
- Window titles
- Browsing history
- Clipboard contents
- Any form of telemetry or analytics — the only network code is the opt-in sync described below, which talks only to a server you configure

## Where data is stored

Everything is written to one JSON file, local to your Mac:

```
~/Library/Application Support/com.adamalnajjar.keystroke-counter/stats.json
```

Writes are debounced — a burst of typing doesn't cause a burst of disk writes — and flushed immediately when the app quits. A handful of UI preferences (e.g. which panel sections are expanded) are stored separately via standard macOS app preferences (`UserDefaults`); these hold interface state only, not activity data.

If you turn on sync, the app also writes `remote.json` in the same folder: a cache of the other Macs' summed counts, so combined numbers show while offline. The sync token is stored in your login Keychain.

## Network access

By default KeystrokeCounter makes **no network requests**. The only networking code is the optional sync feature (`SyncClient.swift`), which is off until you turn it on and enter a server URL and token.

With sync on, the app sends to **that server only**, over HTTPS:

- a random device ID (generated by the app, not derived from your hardware) and your Mac's name
- this Mac's lifetime keystroke and click totals and its "since" date
- per-day keystroke and click counts, per-key frequency tallies, and per-app event counts — exactly what's in `stats.json`

It never sends typed content, key sequences, window titles or anything not already in `stats.json`. The server software is in this repository (`server/`) and is meant to be self-hosted: there is no shared or third-party server. Turning sync off stops all network activity. To remove synced data from the server, delete that device's rows from its SQLite database (`data/sync.db`).

## Accessibility permission

macOS requires Accessibility permission for any app that wants to observe keyboard or mouse events happening system-wide (i.e., while other apps are frontmost). There is no separate, lighter-weight "counting only" permission — Accessibility is the only mechanism macOS offers, and it's what makes this app's core feature possible at all.

**What it allows KeystrokeCounter to technically observe:** while the permission is granted, macOS delivers key-down and mouse-down events happening anywhere on the system to the app.

**What KeystrokeCounter actually does with those events:** for each key press, it derives a short label (like `a`, `space`, or `return`) and increments that key's tally — the raw event is not logged, stored, or transmitted in any other form. For each click, it increments a click counter. In both cases it also notes the frontmost app's name for the "top apps" breakdown. Nothing else is read from the event.

**If you deny or haven't yet granted the permission:** the app still launches normally and shows its menu-bar panel, with a banner prompting you to grant access. Until you do, macOS simply does not deliver events to the app, so counts stay at zero — there's no degraded or partial monitoring happening in the background.

## Third-party services

None. Specifically, KeystrokeCounter includes:

- No analytics or usage-tracking SDK
- No advertising SDK
- No cloud or backend service of any kind
- No third-party dependencies at all — the project links only Apple's own frameworks (AppKit, SwiftUI, Charts, UserNotifications, ServiceManagement)

## Source-code transparency

The entire app is open source in this repository. You don't have to take any of the above on trust — the code that requests Accessibility permission, handles every keyboard and mouse event, and writes statistics to disk is all readable, in particular `EventMonitor.swift`, `KeyName.swift`, and `StatsStore.swift`.

## Data deletion

The panel's **Reset** action zeroes your lifetime keystroke and click totals, resets the "since" date, and clears which milestones have already fired (so they can be reached again). It does **not** delete your daily history — the per-day charts and most-used keys/apps breakdowns are kept intentionally, so long-term charts survive a reset.

There is currently no in-app "erase everything" button. To fully remove all stored data, quit the app and delete:

```
~/Library/Application Support/com.adamalnajjar.keystroke-counter/
```

Note that, as with most Mac apps, simply deleting or uninstalling KeystrokeCounter does not automatically remove this folder, since it lives outside the app bundle in your local Application Support directory — you'll need to delete it separately if you want a clean slate.
